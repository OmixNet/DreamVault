# v0.6.7 — P3-8 评审 §3 修复 (金标评测集)

## 评审发现 (§3)

MockLLM 默认 handler 对 verify 恒答 YES、对矛盾仅凭关键词触发 — **所有闸门测试测的是管道连通性, 不是判别力**. 建议建一个 30 条的金标评测集 (10 有据教训 / 10 幻觉 / 10 对矛盾), 用真实 Ollama 跑 verify 与 conflicts 的精确率/召回率, 写进 CI 之外的 `make eval`. 没有这个数字, 三道闸的"防幻觉"只是结构上的承诺.

## 修复

### 30 case 金标评测集 (EvalDataset.swift)

- `EvalCategory`: `.verifiedTrue` / `.hallucinated` / `.contradictionPair`
- `EvalPhase`: `.verify` / `.contradiction` (调哪个闸)
- `ExpectedVerdict`: `.yes` / `.no` / `.ok` / `.conflict` / `.ambiguous`
- `EvalCase`: id, category, phase, systemPrompt, userPrompt, expectedVerdict, groundTruthNote
- 30 case 拆:
  - **V-01..V-10 verified-true**: 真实教训有证据, verify 应返 YES
  - **H-01..H-10 hallucinated**: 凭空捏造 / 证据不足 / 跟 evidence 矛盾, verify 应返 NO
  - **C-01..C-10 contradiction**: 2 条不能同时为真, 矛盾应返 CONFLICT
- 中英文混合 (NLEmbedding zh-Hans 实测, 跟 dream 真实场景一致)
- 真实 LLM 风格输入 (不留可猜 keyword — 防 LLM 走 keyword 投机)
- `groundTruthNote` 必填 (防 ground truth 漂移)

### EvalRunner (EvalRunner.swift)

- 跑 dataset, 调 LLM provider, 跟老 Consolidator / ContradictionDetector **同款** keyword 解析
  (评测跟生产代码用同一套解析逻辑, 不是 P3-5 还没接管的简化版本)
- 解析辅助: `containsYes` / `containsNo` / `containsConflict` / `containsOk` (P3-2 fix 否定词窗口 5 词)
- `EvalReport` + `EvalAggregate` (P/R/F1) + 按 phase/category 拆

### EvalReportMarkdown (EvalReport.swift)

- 头 + 总 P/R/F1 + 按 phase 拆 + 按 category 拆 + 错 case 详情表 + 全 case 表
- 输出 markdown, pipe-friendly, 可写文件

### CLI + Makefile (评测集成)

- `Sources/dream/CLI.swift`:
  - `case "eval"` + `cmdEval` (P3-8: 跑金标评测集)
  - 参数: `--llm mock|ollama`, `--phase verify|contradiction|all`, `--report <path>`
  - 退出码: 0 = 全对, 1 = 有错 (但仍输出报告供 review)
- `Makefile`:
  - `make build / test` (常规)
  - `make eval` (mock 快速 smoke, ~1s, 30 case)
  - `make eval-ollama` (真实模型 5-30min, 需本机 Ollama daemon)
  - 报告默认写 `docs/eval-YYYY-MM-DD.md`

## P3-8 价值 (评审 §3 量化)

`make eval` 真跑实测 (mock provider, keyword 解析):
- **总 accuracy 30%** (9/30). **这正是评审 §3 强调的**: MockLLMProvider 缺判别力
- verify 闸: 40% (20 case)
- contradiction 闸: 10% (10 case, 9 ambiguous)
- hallucinated 全错 (mock 恒 YES, 防 false negative 没保护)
- verifiedTrue 80% (多数 verified 对)

`make eval-ollama` 真实价值 (本机需 Ollama):
- 用 llama3.1 / qwen2.5 等真实模型跑 30 case, 量化 verify / conflicts 精确率/召回率
- 评审 §2.3 推荐 qwen2.5:3b 当裁判 (裁判任务不需要大模型, 成本低)
- 30 case 跑约 5-30 分钟 (取决于 model size + GPU)
