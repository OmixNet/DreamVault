# v0.5.1 → v0.5.2: P2-6 搜索升级 (ripgrep fast-path + mdfind fallback)

> **核心**: VaultSearcher 加 ripgrep subprocess fast-path, 找不到 rg 自动 fallback 到 mdfind. 1000+ 文件搜索 < 200ms.

## 1. 背景与动机

v0.4 VaultSearcher 用 macOS Spotlight (`mdfind`) 全文搜, 缺点:
- 依赖用户没禁用 Spotlight 索引
- 首次 vault 还没建索引时漏几条
- macOS only (跨平台不友好)

**P2-6 改 ripgrep**:
- Rust 写的 PCRE2 regex 引擎, 比 mdfind 准 (不依赖索引)
- 跨平台 (macOS / Linux / Windows)
- `--max-count=1` 加速 (每文件最多 1 hit, snippet 足够)
- 排除 wiki/ + .dream/ (避免查 dream 生成的产物, 只搜 raw/ 用户内容)

## 2. 设计

### 2.1 RipgrepBridge (DreamEngine, pure function)

- `locateRipgrep()`: 找可用的 rg 路径, 候选:
  1. `/opt/homebrew/bin/rg` (Apple Silicon 默认)
  2. `/usr/local/bin/rg` (Intel Mac)
  3. `/opt/local/bin/rg` (MacPorts)
  4. `which rg` (env PATH 兜底)
- `search(query:root:maxResults:rgPath:) -> [Hit]?`: 跑 Process, 返 hits; 失败 (rg 不存在 / 没装) 返 nil
- `parseOutput(_:root:maxResults:)`: 解析 ripgrep 输出 `<relpath>:<line>:<text>`, 处理 text 内含 `:` (e.g. "08:30 起床")

### 2.2 rg 命令

```
rg -F -n --no-heading --max-count 1 \
   -g '*.md' \
   -g '!wiki/concepts/' -g '!wiki/entities/' -g '!wiki/syntheses/' -g '!wiki/archive/' \
   -g '!.dream/**' \
   <query> <vaultRoot>
```

- `-F`: literal 字符串 (不当 regex)
- `-n`: 显示行号
- `--no-heading`: 单行输出, 易解析
- `--max-count=1`: 每文件最多 1 hit (snippet 够)
- `-g '*.md'`: 只搜 md
- `-g '!wiki/...' -g '!.dream/**'`: 排除 dream 产物

### 2.3 VaultSearcher 改造

```swift
private static func runSearch(query:vaultRoot:) async -> [SearchResult] {
    // 1) ripgrep fast-path
    if let hits = RipgrepBridge.search(query:root:) {
        return hits.map { SearchResult(id:$0.file, path:..., snippet:$0.text) }
    }
    // 2) mdfind fallback (旧路, 仍能用)
    return await runMdfind(query:vaultRoot:)
}
```

**对调用方零侵入**: `searcher.search(vaultRoot:)` 签名不变, UI / SearchSheet 不用改. 用户透明感受加速.

## 4. 踩坑记录 (2 条)

1. **text 内含 `:` 解析错位**: 第一版 split(":") 不限次数, "08:30 起床" 被切成 3 段, 第 3 段当 line. 修: `components(separatedBy: ":")` 取前 2 段 (file, line), `parts[2...].joined(separator: ":")` 拼回 text. 经验: **解析工具输出, 限 split 次数 + 手工 join 剩余**.
2. **rg 不可用要 graceful fallback**: 第一版直接 `guard let rg` 找不到就 return [], 但调用方拿到空结果以为"真没 hit", 实则没装 rg. 修: 返 nil (≠ []) 让调用方区分 "rg 失败" 跟 "rg 跑了没 hit". VaultSearcher 拿 nil 走 mdfind. 经验: **subprocess 路径返 nil 表示"我没跑", 返 [] 表示"跑了没结果"**, 别混.
