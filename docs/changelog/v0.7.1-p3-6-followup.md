# v0.7.1 — P3-6 follow-up 矛盾预筛 embedding topK + KnowledgeGraph semanticEdges

## 评审发现 (P3-6 §4.1 follow-up)

P3-6 搭了 `EmbeddingProvider` 协议 (`NLEmbeddingProvider` + `CachedEmbeddingProvider` + `StaticEmbeddingProvider` + `EmbeddingMath.cosineSimilarity`), 但**生产路径仍未用上**:
- `Prescreener.prescreen()` 仍走老 token/Adamic-Adar 路径
- `KnowledgeGraph` 只有"来源重叠"边 + Adamic-Adar 关联分, 没有跨文件同主题连边
- `DreamConfig` / `DreamCycle` 也没字段注入 embedding

## 修复

### 1. Prescreener 矛盾预筛 embedding topK 模式

- `Prescreener.init` 加 3 参数: `embeddingProvider: EmbeddingProvider?` / `embeddingTopK: Int = 5` / `embeddingSimilarityThreshold: Double = 0.5`
- 老路径行为保留 (`embeddingProvider: nil` → 跟 v0.7.0 完全一致, 0 退化)
- 注入 provider 后: 算 candidate vs existing cosine, 排序取 topK (默认 5)
- **评分优先级**: embedding (2.0+) > token (1.0) > Adamic-Adar (0+)
- embedding topK 内 pair 走 LLM, 老 token/AA 路径补漏 (跨语言 / 跨 token 场景)
- **跨语言场景**: "机器学习" vs "machine learning" → 老 token 漏, embedding 捕到
- **成本**: O(N×M) → O(N×topK). 10 candidate × 500 durable = 5000 → 10×5 = 50
- `Prescreener.Result` 加 `embeddingPrescreenEnabled` 标志 (UI 报告用)

### 2. KnowledgeGraph.semanticEdges 跨文件同主题连 embedding 边

- **纯函数**: 不修改 graph 本身 (immutable), 返回建议边 `[(a, b, score)]`
- 批量算 embedding (走 provider + cache), 两两 cosine ≥ threshold 入选
- 已有边跳过 (跟"来源重叠"边互补, 不重复)
- `maxPerNode` 限热门节点刷屏 (默认 5)
- threshold 默认 0.85 (跟 `EmbeddingMerge.cosineMergeThreshold` 对齐)
- **图谱可视化层 (P2-2) 集成留给 v0.7.x follow-up** (本 PR 只基础设施)

### 3. DreamConfig / DreamCycle 集成

- `DreamConfig` 加 3 字段: `embeddingProvider` / `embeddingTopK` / `embeddingSimilarityThreshold`
- `DreamConfig.productionDefault` 默认无 embedding (**向后兼容**, 不强依赖 NLEmbedding)
- `DreamCycle.runOnce` 注入 `ContradictionDetector` (矛盾预筛) + `mergeSimilar` (同质合并, P3-6 已搭的 embedding 路径之前 `nil`, 现在从 config 注入)
- `ContradictionDetector.init` 加 3 参数透传给 Prescreener
