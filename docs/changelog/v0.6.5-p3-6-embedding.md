# v0.6.5 — P3-6 评审 §4.1 修复 (本地 embedding 3 用)

## 评审发现 (§4.1)

NLEmbedding / NLContextualEmbedding 系统自带离线免费. 一份记忆文本向量可同时解决
3 个独立需求 (评审明确给出):
1. 同质合并 (§1.1 修复核心): 新教训 vs ledger 余弦相似 > 阈值 → 合并 source
2. 矛盾预筛: 只对相似度中高的记忆对调 LLM, O(N×M) → O(top-k)
3. 图谱语义边: 跨文件同主题连边, 补 2.2 信号稀薄

中文支持需实测 `NLEmbedding.sentenceEmbedding(for: .simplifiedChinese)` 可用性, 不行
回退字符 n-gram Jaccard.

## 修复

- **`EmbeddingProvider` 协议**: `embed(_ text: String) -> [Double]?` + `dimension: Int`.
  nil = embedding 不可用 (offline 模式 / 不支持该语言). 0 依赖, 走 NaturalLanguage 框架.
- **`NLEmbeddingProvider`**: macOS 12+ 用 NLEmbedding. 3 mode: `.simplifiedChinese` /
  `.english` / `.auto` (CJK → zh-Hans, 否则 en). 实测 macOS 14:
  - EN 维度 512, ZH 维度 640
  - ZH "机器学习" vs "深度学习" = 0.94
  - ZH "机器学习" vs "苹果水果" = 0.81 (无关但 NLEmbedding 整体偏高)
- **`CachedEmbeddingProvider`**: in-memory 缓存 (key = text). 避免重复算向量.
- **`StaticEmbeddingProvider`**: 测试 mock, 返固定 vector 或 nil (模拟离线).
- **`EmbeddingMath.cosineSimilarity`**: 零向量 / 长度不一致 graceful fallback 0.0
  (避免 NaN). 鲁棒性.
- **`EmbeddingMerge` (P3-1 升级)**: 双信号 OR (cosine >= 0.85 OR jaccard >= 0.6) 判 merge.
  embedding 不可用时 fallback P3-1 jaccard 兜底.
  - 阈值 0.85 (而非 0.7): NLEmbedding 中文 cosine 整体偏高, "机器学习" vs "苹果水果"
    也 0.81, 0.7 误合风险高. 0.85 平衡.
- **`DreamCycle.mergeSimilar`**: 加 `embeddingProvider: EmbeddingProvider? = nil` 参数.
  embedding 可用 → 双信号 OR. 不可用 → 走 P3-1 jaccard (向后兼容).
- **`DreamCycle.runOnce` mergeSimilar 调用**: `embeddingProvider: nil` (DreamConfig 升级时
  再注入. 当前 production user 走老 jaccard 路径, 无回归).
