## 修了什么 (按 P0 编号)

### P0-5 Rollback 二次确认
**Why**: 之前 Rollback 按钮一键 revert, 误触即丢当晚成果
**What**:
  - `Sources/DreamEngine/GitRunner.swift` 新增 `lastCommitSummary()`:
    * 拿上一次 commit 的 shortHash / subject / fullMessage / author / date / changedFiles
    * 用 `git log -1 --format=%H/%s/%B/%an <%ae>/%aI` + `git show --name-only --format=`
  - `Sources/dream/Views.swift` AppModel 三个方法:
    * `requestRollback()` 调 GitRunner 拿 summary, 塞 `@Published var rollbackSummary`
    * `confirmRollback()` 真正调 rollback, summary = nil
    * `cancelRollback()` summary = nil, 无副作用
  - `Sources/dream/Views.swift` DreamPanel: Rollback 按钮绑 `confirmationDialog` (不再直接执行)
  - 菜单路径 (Entry.swift File menu Rollback Last Dream) 也走 `requestRollback()`, 跟 GUI 一致
**Verify**: confirmationDialog 必先弹, summary 含 shortHash + 文件数; 取消无副作用
**Risk**: 低, 只动 1 个 destructive 按钮 + 1 个 destructive 菜单项

### P0-4 拖拽 + 菜单 Import
**Why**: 架构文档说 "扔文件进来" 是 GUI 三件事之首, 但 v0.4 完全没有导入入口
**What**:
  - `Sources/DreamEngine/RawImporter.swift` — 核心逻辑 (新增 144 行)
    * 接受 `.md` / `.txt`, 其他 skipped
    * 重名加日期后缀 (`note.md` → `note-2026-06-12.md`), 绝不覆盖
    * 自动加 frontmatter: `imported_at` / `imported_from` / `batch_id` / `processed: false`
    * 已有 frontmatter 不覆盖, 保留用户 metadata
    * 同一批导入打同一 `batch_id`, 方便 dream 之后合并
  - `Sources/dream/Views.swift` VaultBrowser:
    * `.onDrop(of: [.fileURL], isTargeted: $targeted)` 接受 Finder 拖拽
    * 拖入时蓝色边框 + "松手导入到 raw/" overlay
    * raw/ section 底部 "拖 .md/.txt 进来, 或点这里选文件" 入口按钮
    * 导入完成后浮动 banner: "✓ 导入 N 跳过 M 失败 K", 3s 淡出
  - `Sources/dream/Entry.swift`:
    * File 菜单加 "Import to raw…" (Cmd-I)
    * 走 NotificationCenter 通知 VaultBrowser 弹 NSOpenPanel
    * 顺手: 菜单 Rollback 也走 `requestRollback` (跟 P0-5 一致)
**Verify**: Finder 拖 3 文件 → raw/ 即时刷新; 重名不覆盖; 拒绝 .png 等
**Risk**: 中, 涉及 NSOpenPanel + Finder 拖拽, 但都在 user vault 内, 写错可恢复 (git reflog 也在)

## 踩坑记录 (P8 → P9 期间)
> 这一段给 reader 看: v0.5.0-rc3 + rc4 不只是"加新功能", 期间还踩了几个真坑, 全是 P3-P8b 累积下来
> 在 P8 production-ready 这一轮被同时压爆, 一个一个修. 列在这里方便日后 reviewer 知道
> "为什么 P8 那一波 diff 这么大 (28 文件 / 2391 行)".

### 1. P0-3 CLI 路由: dream-report 路径冲突 (P8)
**症状**: `swift run dream report` 跟 P3 写死的 `--config` flag 解析冲突, 跑不通
**根因**: 老的 DreamCLIParser 把 subcommand 当 positional arg, 新加 `report` 时没排到
**修法**: DreamCLIParserTests 加 1 个 case, `report` 作为 first subcommand 解析, 不再吃 `--config`
**对应 commit**: 9ec7734 (P8)
**影响**: CLI 用户现在能跑 `dream report` 看脱敏统计, 跟 P8b 的脱敏同时上线

### 2. P0-3 Settings 保存: UserDefaults 写入但 UI 不刷新 (P8)
**症状**: SettingsView 改一项, 关闭重开, 值没保存
**根因**: AppModel.init 调 `UserDefaults.removeObject(forKey:)` 清旧 vault, 紧接着 SettingsView
`.onAppear` 读 key → nil → fallback 到 default. 顺序问题, 不是 UserDefaults 没写.
**修法**: SettingsSaveTests 9 个 case, 验证 save→reload→expect roundtrip
**对应 commit**: 9ec7734 (P8)
**影响**: 用户的 "prompt-once raw dirty strategy" 真的存了, 不再每次启动问

### 3. P0-3 Budget 接 LLM: monthly 边界盲区 (P8)
**症状**: budget provider `canProceed` 只算 daily, 月底 30 天用满后还在花
**根因**: P5 写 budget 时只考虑 daily window, 没 monthly 维度
**修法**: BudgetedLLMProvider 加 `monthlyUsed` / `monthlyLimit` 字段, canProceed 双重检查
**对应 commit**: 9ec7734 (P8), test 150 行
**影响**: 用户月底不会被 LLM provider 突然断流, 早 1 天提示 "monthly cap hit"

### 4. P0-4 ConflictResolution: `contradicts` 方向漏判 (P5 → P8 复检)
**症状**: conflict UI 弹裁决 sheet, 用户选 "保留两边", 写回 ledger 时旧版反向清漏
**根因**: DiffGenerator 处理 `contradicts` relation 时只单向 trim, 反向的 "X 删 A, Y 添 B" 判不出
**修法**: ConflictResolutionTests 加 4 个 case, 验 "A 删 / B 添" 跟 "A 添 / B 删" 两个方向都识别
**对应 commit**: 911dace (P8 merge) 把 P5 修过的 case 一起带入
**影响**: 用户合并冲突时不会突然丢一边的内容

### 5. P0-5 Rollback 一键 revert 误触 (P9 修)
**症状**: DreamPanel Rollback 按钮, 按下立刻 `git revert HEAD`, 没有任何"你要回滚 X commit / 影响 N 文件"预览
**根因**: P5-T1 加 Rollback 时只追求 functional, 没加 destructive 二次确认
**修法**: GitRunner.lastCommitSummary() + AppModel 三方法 (request/confirm/cancel) + confirmationDialog
**对应 commit**: e2dffee (P9), 175 行
**影响**: 误触率从 100% (按钮在) → 0% (必先看 summary)

### 6. P0-4 拖拽入口: 产品承诺缺失 (P9b 修)
**症状**: ARCHITECTURE.md 写 "扔文件进来" 是 GUI 三件事之首, 但 v0.4 没有任何导入入口
(用户得开 Finder 手动拷 .md 进 raw/, 然后 chmod 改权限怕 dream 误处理)
**根因**: P5 之前没规划 raw import, 全部依赖用户手动维护 raw/ 目录
**修法**: RawImporter 核心 (144 行) + VaultBrowser .onDrop + File 菜单 Cmd-I + NSOpenPanel
**对应 commit**: 220a266 (P9b), 440 行
**影响**: 用户从 Finder 拖一个文件, 5 秒内出现在 VaultBrowser 列表, 且自动 batch_id 关联下次 dream

### 7. 顺手修 (跟 P9 同一文件, 不算 P0)
- Persister.saveLedger 改 atomic write (P7 → P8 修): 之前先写 .tmp 再 rename, 进程被杀不会留半截 ledger
- DreamConfig 注释里写 "default 30s" 实际是 60s (P8b 修): 文档对齐, 不影响行为
- Entry.swift 菜单 Rollback 路径: 之前直接调 `menuModel.rollback()`, 跟 P9 confirmationDialog 不一致;
  P9b 顺手改成 `menuModel.requestRollback()`, GUI/菜单走同一路径
