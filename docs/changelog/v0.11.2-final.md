## P1.3: Markdown 链接加 .link attribute (缺陷报告 §3.3 P1.3)

**根因** (`Sources/dream/MarkdownHighlighter.swift` 老实现, v0.11.0 ship):
```swift
attr.addAttributes([
    .foregroundColor: linkColor,
    .underlineStyle: NSUnderlineStyle.single.rawValue,
], range: textRange)
// 没 .link → 点击触发 NSTextView 默认 click handler, 走 plain text 模式
// delegate.textView(_:clickedOnLink:at:) 不调用
```

**修法** (P1.3 修复): 解析 url 字符串 → `URL(string:urlString)` → 设 `.link` attribute on text range
```swift
var attrs: [NSAttributedString.Key: Any] = [
    .foregroundColor: linkColor,
    .underlineStyle: NSUnderlineStyle.single.rawValue,
]
if isClickable { attrs[.link] = URL(string: urlString) }
attr.addAttributes(attrs, range: textRange)
```

**效果**:
- 点击 `[click](https://example.com)` → NSTextView delegate 触发
  `textView(_:clickedOnLink:at:)` → URL scheme != 'dreamvault' → 返 false
  → NSTextView 默认走 `NSWorkspace.shared.open(url)` → 浏览器打开
- 点击 `[[wikilink-id]]` (dreamvault://) → WikiLinkExtractor 自己加了
  `.link` → delegate 触发 → `onWikilink` closure 调, 切到该 memory
- 跟 wikilink 0 冲突 (skipRanges 跳过 wikilink 范围, 不重复加 .link)

**边界**:
- 无效 URL (含空格 / 不合法字符) → `URL(string:)` 返 nil → 不设 `.link`
  仅装饰, 避免 NSTextView 内部报错
- `file://` URL 也可点 (NSWorkspace.open 自动调系统打开)
- 跳过 wikilink 范围 (skipRanges 内的不重复加 .link)

**3 new tests** (P1.3 修复):
- testMarkdownLink_tealAndUnderline_andClickable (拆原 test 8, 加 .link 验证)
- testMarkdownLink_invalidURL_noLinkAttribute (无效 URL 不设 .link)
- testMarkdownLink_fileURL_clickable (file:// 也可点)
- testMarkdownLink_skipRanges_noLinkAttribute (skipRanges 不重复加 .link)
