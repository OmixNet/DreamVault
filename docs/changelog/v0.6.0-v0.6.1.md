# v0.6.0 → v0.6.1: P3-2 CONFLICT 解析 bug 修复 (评审 §2.4)

> **核心**: ContradictionDetector 解析 LLM 输出从 `contains("CONFLICT")` 改成首词匹配 + JSON 支持 + 否定上下文检测. 修评审 §2.4 bug: "NO CONFLICT" 老代码判 true (反向误判), 新代码判 false.

## 1. 背景与动机

评审 §2.4 指出: `ContradictionDetector.conflicts()` line 49 用 `answer.uppercased().contains("CONFLICT")` 判断矛盾. **致命 bug**: 本地小模型最自然的否定表述 "NO CONFLICT" (或 "A and B are NOT in CONFLICT") 会被判为矛盾. 真实模型下会**大量反向误判**, 淹没人工裁决.

## 2. 设计

### 2.1 parseConflictAnswer (新, static func)

```swift
public static func parseConflictAnswer(_ answer: String) -> Bool
```

**三层降级策略** (跟 LLM 灵活输出对齐):

1. **JSON 格式**: `{"conflict": true/false}` / `{"CONFLICT": true/false}` (大小写不敏感). 兼容 markdown ` ```json ` 围栏
2. **首词匹配**: 取首行首 token. 命中 `CONFLICT/YES/TRUE` → true, `OK/NO/FALSE/NONE/NIL` → false
3. **全文兜底**: 找 `CONFLICT` 位置, 跟前面 5 词 (15 字符) 内的否定词 (NO/NOT/NONE/NEVER/NIL/ISN'T/AREN'T) 比. 命中否定词 → false, 否则 true

### 2.2 stripMarkdownFence (新 helper)

跟 MarkdownRenderer / SourceRefValidator 已有工具一致 — 剥掉 LLM 偶发包的 ` ```json ... ``` ` 围栏, 让 JSON parse 跟首词匹配能跑.

## 4. 踩坑记录 (3 条)

1. **Swift raw string 嵌 ` ``` `**: `#"```json\n..."#` 不工作, `""` 跟 `"""` 在 raw string 里是结束符. 改用普通 string `"```json\n..."`. 经验: **Swift 5.5+ raw string 遇到 ` ``` ` / 嵌套 raw string 容易踩, 测试时手动验证**.
2. **否定词窗口太窄**: 第一版兜底看 CONFLICT 前面 6 字符, "Not a CONFLICT" 中 "Not" 跟 "a" 隔 1 词, 不在 6 字符内. 扩到 5 词 / 15 字符, 覆盖 "Not a CONFLICT" / "There is NO CONFLICT" / "None of these conflict". 经验: **否定词检查要跨词窗口, 不能用固定 char 数**.
3. **JSON 解析 + 兜底 顺序**: 第一版先 JSON, JSON 失败回首词. 但 `testJSONMalformedFallsBackToFirstWord` 测的是 `{conflict: true}` (无引号, 非法 JSON), 应被首词匹配兜底成 false (因为首 token 是 `{`). 实际 `parseConflictAnswer` 真这样跑 — JSON 解析失败 fallthrough 到首词, 首 token `{` 不在已知 switch, 进 default 走全文兜底. 测试 pass. 经验: **多层降级顺序很重要, 每一层都有意义, 不要跳级**.
