# v0.5.0-rc7 → v0.5.0-rc8: P0-8 冲突裁决大 sheet 模式

> **核心**: 把 inline 拥挤 4 buttons (340pt sidebar 太窄) 改为独立 760x520 sheet, 一次一对左右并排, 3 主 button (Keep A/Keep B/Archive Both) + Merge 单独. 双向 contradicts 清理沿用 P8 修复.

## 1. 背景与动机

P3-T1 把冲突裁决做在 sidebar 行内, 每条记忆一个 row, 展开后 4 按钮挤 340pt 宽度. P8 加了 Merge 按钮 + 修了 keepB/archiveBoth 双向 contradicts cleanup. 但 sidebar 太挤:
- 每条记忆的 contradicts 列表展开后**对手们只显示 1 句 text, 看不到 source**
- 4 按钮一字排开, 控制 size=small 仍拥挤
- 用户操作 "点 row → 展开 → 选 action" 三步, 一屏只能 1 条

**P0-8 重做**: 弹独立 sheet, 一次一对, 左右并排, 3 button 底部 + Merge 单独 + Cmd-A/Cmd-B 快捷键 + 翻页按钮. sheet 760x520, 整段 source 列表可滚. 全解决自动关 sheet.

## 2. 设计

### 2.1 双模式并存

- **P3-T1 inline 模式**: 保留, sidebar 仍可点 row 展开 + 选 4 button (向后兼容)
- **P0-8 sheet 模式**: 新增, sidebar 多一个 "Review" 按钮 → 弹 760x520 sheet

两个模式共用 `resolve(_:mem:)` 跟 `mergeCommit` 逻辑, 双向 cleanup 一致.

### 2.2 ConflictResolutionSheet 结构

```
┌────────────────────────────────────────────────────────────┐
│ Conflict Resolution                                       [×]│
│ 3 pairs need decision · showing 1/3                          │
├────────────────────────────────────────────────────────────┤
│ ┌─A───────┐    ⟷ contradicts    ┌─B───────┐                  │
│ │ use     │                      │ use     │                  │
│ │ SwiftUI │                      │ AppKit  │                  │
│ └─────────┘                      └─────────┘                  │
│ ┌─Sources:─────────────────────────────────────────────┐    │
│ │ • raw/swiftui-note.md:1  excerpt of swiftui text...  │    │
│ │ • raw/appkit-note.md:1   excerpt of appkit text...   │    │
│ └──────────────────────────────────────────────────────┘    │
├────────────────────────────────────────────────────────────┤
│ [🗑 Archive Both] [🅰 Keep A] [🅱 Keep B] [⇄ Merge…]  ‹ › │
└────────────────────────────────────────────────────────────┘
```

- **Header**: 标题 + "X pairs need decision · showing N/M" + Close 按钮 (Esc 关)
- **Body**: 左右并排 (蓝色 A / 灰色 B 圆圈标识) + 中间 `arrow.left.and.right` 分隔
- **Sources 段**: 可滚 80pt 高, monospace caption, 列双方 source (file:line + excerpt 120 字符)
- **Footer**: 4 button 等宽 + 翻页 ‹ › (只在多对时启用)
  - **Archive Both** = destructive (红, 拖 trash icon)
  - **Keep A** = `.keyboardShortcut("a", modifiers: [.command])` (Cmd-A)
  - **Keep B** = Cmd-B
  - **Merge…** = 单独, 走原有 MergeSheetView (不动 resolution 状态)
  - 翻页 ‹ / › = 切到上一对 / 下一对, 不解决

### 2.3 resolve 流程

- 用户点 button → `onResolve(choice, mem)` callback → 走 P8 修复过的 resolve 函数
- resolve 写 ledger.json + git commit + 写 .dream/conflict-resolutions.log
- 100ms 后 `advance()` 重新读 ledger, conflicts 列表少一个, 自动跳下一对
- 0 对时 `onDismiss()` 关 sheet

### 2.4 公开 API

- `ConflictResolutionView.body` 加 `@State showSheet: Bool = false` 跟 `sheetIndex: Int = 0`
- 新增 `ConflictResolutionSheet` struct (internal, 在同文件), 跟主 view 解耦
  - `init(ledger:onResolve:onMerge:onDismiss:)` — 4 callback
  - `ledger` 是值类型, 每次 callback 后 SwiftUI 重新求值 body

## 4. 踩坑记录 (3 条)

1. **`public init` + internal 类型编译错**: `ConflictResolutionSheet.init` 标 public, 但 callback 用了 nested `ConflictResolutionView.Resolution` (internal). Swift 不让 public init 暴露 internal 类型. 修: 把 sheet 跟 init 都改 internal (不跨模块用).
2. **Callback signature 跟 caller 标签不一致**: 第一次 sheet 写 `onResolve(choice, mem)` closure 形式 (无 label), 但 caller 写 `onResolve(.keepA, mem: mem)`. Swift 强标签检查, compile fail. 修: 用 closure tuple destructuring (`{ choice, mem in ... }`) 跟 caller 用 positional (`onResolve(.keepA, mem)`).
3. **Sed 改 `mem:` label 误改 view 自身调用**: 第一次 sed 把 `onResolve(.archiveBoth, mem: mem)` 改成 `onResolve(.archiveBoth, mem)` — 但 view 内 `resolve(.archiveBoth, mem: mem)` 这个是 `func resolve(_:mem:)` 调用, label 正确. sed -i 用 `g` (replaceAll) 把不相关 3 个 caller 错改. 修: 用 `s|onResolve(\.x, mem: mem)|...|g` 限定 onResolve 前缀.
