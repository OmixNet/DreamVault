## 评审 §2.3 / §4.1 真正想要的"开箱即用"

v0.7.1 搭了完整 infrastructure (`EmbeddingProvider` 协议 + `NLEmbeddingProvider` + `CachedEmbeddingProvider` + `StaticEmbeddingProvider` + `Prescreener` 注入 + `KnowledgeGraph.semanticEdges` + `DreamConfig.embeddingProvider` 字段), 但 `DreamConfig.productionDefault` 默认 `nil` — 用户必须显式配才用得上, **评审 §2.3 / §4.1 真正想要的是开箱即用, macOS 12+ 默认开 NLEmbedding**.

## 修复

### 1. DreamConfig.productionDefault 真集成 NLEmbeddingProvider

```swift
public static let productionDefault: DreamConfig = {
    let nl = NLEmbeddingProvider(mode: .auto)
    let provider: EmbeddingProvider? = nl.dimension > 0
        ? CachedEmbeddingProvider(inner: nl)
        : nil
    return DreamConfig(embeddingProvider: provider)
}()
```

- 走 `CachedEmbeddingProvider(inner: NLEmbeddingProvider(mode: .auto))` 包装 (NLEmbedding 系统自带, 离线, 免费)
- **macOS 12+ NLEmbedding 可用** (`dimension > 0`) → `CachedEmbeddingProvider` 启用
- **不可用** (macOS 11- / 系统语言不支持) → `nil`, 走 P3-6 老 token/AA 路径 (**0 退化, 自动降级**)
- `productionDefault.consolidation` 仍是 3 步 (P3-3 §1.2 invariant 保留)

### 2. DreamConfig.unconfigured

- 显式无 embedding 配置 (测试 / 离线用)
- 跟 v0.7.0 / v0.7.1 productionDefault 行为一致 (nil provider)

### 3. 修复 P36FollowupTests 隐藏 flake

老代码:
```swift
XCTAssertTrue(edges.contains { $0.a == "m1" && $0.b == "m2" && $0.score > 0.9 })
```

**问题**: `KnowledgeGraph.semanticEdges` 内部 `for id in nodes` (Set) 迭代顺序非确定, 边可能 `(m1, m2)` 或 `(m2, m1)`. v0.7.1 提交时这条 case 在 full suite 跑偶尔 fail (Set 顺序依赖), 当时没暴露因为 `583/583` 报告时序.

**修法**: 解构 tuple + `(m1, m2) || (m2, m1)` 双边断言 + 阈值 0.9 兼容.
