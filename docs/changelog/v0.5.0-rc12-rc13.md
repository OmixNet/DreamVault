# v0.5.0-rc12 → v0.5.0-rc13: P2-4 偶然唤回 (serendipity 1-line)

> **核心**: vault 启动时从 "30+ 天没看" 的 durable memory 里选 1 条, 顶部 banner 唤起. 减少 recall decay.

## 1. 背景与动机

用户写 vault 几个月后, 早期记忆自然变冷 (Reinforcer 已做 lastAccess 跟踪). 但**没人主动重看老记忆** — decay 越来越快, 价值流失.

**P2-4 serendipity**: vault 启动时**主动给用户 1 条老记忆**, 1 行 banner, "30 天前你看到 ...". 唤回老记忆, 减少主动 recall 成本.

## 2. 设计

### 2.1 SerendipitySelector (DreamEngine, pure function)

从 vault 选 1 条 "好久没看" 的 durable memory.

**规则**:
1. 只看 `status == .durable` (candidate 没成型不算)
2. `lastAccess` 距今 ≥ 30 天 (默认) 且 ≤ 90 天 (太老唤回也没用)
3. 候选 ≥ 1 才返回, 否则 `nil` (没合格就不显示 banner)
4. 多个候选: 优先离 45 天最近 (sweet spot, 30-60 天唤回价值最高), top 3 用 stable hash 选 1
5. **确定性**: 同样 inputs + 同日 = 同样 pick (同日多次启动不会变)

**默认 minDays = 30** — 30 天不看的记忆 = 真正变冷了, 该唤回. ≤ 30 天的还在用户短期记忆, 不用 banner 推.

### 2.2 SerendipityBanner (SwiftUI)

主窗顶部 safeAreaInset, 黄色背景, lightbulb 图标:
- 主行: "**N 天前你看到**: <memory 摘录>"
- "Open" 按钮 (borderedProminent, 跳到记忆)
- "×" 按钮 (dismiss, banner 这次启动不再显示)

跟 update banner 同位置, 同模式. 多个 banner 一起 (update 在上, serendipity 在下).

### 2.3 集成流程

`MainView.onAppear` → 调 `SerendipitySelector.pick(from: model.ledger.memories)` → 存到 `@State serendipityPick` → `.safeAreaInset` 渲染 banner.

**Dismiss 状态**: `@State serendipityDismissed = false`, 用户点 Open / × 设为 true, 这次 session 不再显示. 跨 session 不持久化 (P10+ TODO: UserDefaults flag).

## 4. 踩坑记录 (3 条)

1. **stableHash 返 Int 负数 mod crash**: `Int(seed) % Int(top.count)` 当 seed = Int.min, `Int.min % -3` 还是负数, `[neg]` crash (Fatal error: Not enough bits). 修: 改 `stableHash` 返 `UInt64`, mod 用 `UInt64(top.count)`. 经验: **mod 之前确保 operand 无符号 / 强制 abs** (Int.abs(Int.min) 仍负).
2. **sweetSpot test 期望太严**: 第一版 test 期望 100% 选 45 天. 实际算法 "top 3 stable hash 选 1", 可能选 30 或 80. 改 test 接受 sweet spot 3 个之一 + 额外 case 验证 "不放 80 时不会选 80". 经验: **算法有 random 元素时, test 验证 invariant 不用 hardcode 期望值**.
3. **确定性的必要**: 同样 vault 同样日期多次启动, 应给用户同一条 serendipity — 否则 banner 跳来跳去很烦. stableHash(id|day) 保证同日稳定, 隔天换一条 (新鲜感).
