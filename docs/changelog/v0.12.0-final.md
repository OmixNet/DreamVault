## 真 P0 (急修, 2 件)

### P0-1: List 单击/双击 row 不开 file

**根因** (`Sources/dream/EditorPane.swift:31` 老实现):
```swift
.onReceive(model.$selectedFile.compactMap { $0 }) { url in
    _ = state.openFile(url)
}
```

`compactMap` 把 `URL?` 压成 `URL`, 第一次 nil → url 时不触发 (正确); 但**同 row 重复
点**不会改 `selectedFile` (已经是 url_A 再点 url_A 还是 url_A), Combine **不发新值**,
`onReceive` 不触发 → 中心区停 Select a note.

**修法** (新 `EditorPane.swift:31-42`):
```swift
.onChange(of: model.selectedFile) { newURL in
    guard let url = newURL else { return }
    _ = state.openFile(url)
    // ... (Reinforcer 逻辑保留)
}
```

用 `onChange(of:)` (macOS 13 兼容版) 监听所有 selectedFile 变化, 包括同 url 重复点
不进 state.openFile() 的情况.

**真伪判定**: 用户 18:35 报"真实窗口坐标单击/双击侧栏条目后, 中心区仍停在 Select a note".
代码静态分析确认是 List selection + Combine onReceive 时序问题. 修法 ✓.

### P0-2: 编辑器桥 (焦点不进, 文本不写盘)

**根因** (`Sources/dream/NSTextViewRepresentable.swift:51-71` 老实现):
- NSTextView 装好后, SwiftUI **不会自动 becomeFirstResponder**.
- 用户点编辑区时, firstResponder 仍是 Sidebar outline (List 节点), textView 不响应
  keyDown, 看起来"输入没反应" → textViewDidChange 不发 → state.buffer 不更新 →
  写盘不写.

**修法** (新 `NSTextViewRepresentable.swift:55-77`):
```swift
if text != context.coordinator.lastSeenExternalText {
    // ... 重设 string / selection / scroll (老逻辑)
    // P0 修复: text 变了 (切文件) → DispatchQueue.main.async 异步抢 firstResponder
    if isEditable {
        DispatchQueue.main.async { [weak textView] in
            guard let textView, let window = textView.window else { return }
            if window.firstResponder !== textView {
                window.makeFirstResponder(textView)
            }
        }
    }
}
```

**为什么只在 updateNSView 抢**: 切文件 → updateNSView 触发 → text 变 → 异步抢
firstResponder. 异步: 避免 view tree commit 中同步抢被覆盖. 只在 editable 抢: raw
只读时让 outline 留焦点 (更符合用户预期).

**真伪判定**: 用户 18:35 报"点编辑区后焦点仍停在 Sidebar outline, 输入测试文本没有
出现在界面". 修法 ✓.

**注意**: 我 (Mavis) 受 macOS TCC 限制, 无法独立 AX 测 click / 输入. 需用户重测
GUI 行为, 见 "重测指引" 末.

### P1-4: RawImporter 已有 frontmatter 不保证 processed:false

**根因** (`Sources/DreamEngine/RawImporter.swift:142-147` 老实现):
```swift
if trimmed.hasPrefix("---") {
    return content  // 已有 frontmatter 不动
}
```

走"无 frontmatter"路径时 line 148-160 加 `processed: false`. 走"已有 frontmatter"
路径时**不动**, 缺 `processed: false` 的文件进 candidate 集后 FrontmatterScanner 不能
正确分流.

**修法** (新 `RawImporter.swift:142-152` + `ensureProcessedFlag`):
```swift
if trimmed.hasPrefix("---") {
    return ensureProcessedFlag(content: content)  // P1-4 修复
}
```

`ensureProcessedFlag` 解析 frontmatter 块, 缺 `processed:` 字段就显式补
`processed: false` 在 `---` 闭合前. 已有 `processed: true` 保留 (用户已声明处理过,
dream 不应擅自翻).

**2 new tests** (`RawImporterTests.swift`):
- `testImport_preservesExistingFrontmatter` 加断言 `processed: false`
- `testImport_preservesExistingProcessedTrue` (新 case): processed:true 保留, 不翻

### P1-5: GUI smoke verify 过浅

**根因** (`scripts/build_and_run.sh:184-196` 老实现):
```bash
if ! lsof -p "$PID" ...; then
    echo "    ⚠ lsof 找不到 vault 路径（GUI 还没打开它，正常）"  # warning
fi
if [ -s "$LOG_FILE" ]; then
    echo "    ✓ 日志已写入 ..."
else
    echo "    ⚠ 日志为空"  # warning
fi
```

lsof miss + 日志空都判 "⚠ warning", verify 仍 PASS → 不能作为发布前 GUI 验证.

**修法** (新 `build_and_run.sh:184-203`):
```bash
sleep 3  # 给 GUI 时间开 file
if ! lsof -p "$PID" 2>/dev/null | grep -q "$VAULT"; then
    echo "    ❌ 进程 3s 内未访问 vault 路径 ($VAULT)"
    FAIL=1  # ← 改 FAIL
fi
if [ -s "$LOG_FILE" ]; then
    echo "    ✓ 日志已写入 ..."
else
    echo "    ❌ 日志为空 ($LOG_FILE)"
    FAIL=1  # ← 改 FAIL
fi
```

### 顺手新 P1: 标题栏版本号 "vv0.5.0 可用（当前 vdev）" 写错

**根因** (`Sources/DreamEngine/UpdateChecker.swift:35-43` 老实现):
```swift
self.currentVersion = currentVersion
    ?? (Bundle.main.infoDictionary?["CFBundleShortVersionString"] as? String)
    ?? "0.0.0"
```

dev build 的临时 .app 没 Info.plist → 走 fallback "0.0.0" → banner 出来
"vv0.5.0 可用（当前 v0.0.0）" 误导用户 (最新 v0.11.2, 不是 0.0.0).

**修法** (新 `UpdateChecker.swift:35-50`):
```swift
let bundleVer = ... ?? "0.0.0"
if bundleVer == "0.0.0" {
    self.currentVersion = "dev"  // 显式标 dev build
} else {
    self.currentVersion = currentVersion ?? bundleVer
}
```

dev build banner 出来 "v0.11.2 可用（当前 vdev）", 明确标 dev.
