# v0.6.2 — P3-3 评审 §1.2 修复 (3 步 CoT 默认开 + 失败跳过)

## 评审发现 (§1.2)

老默认 `useThreeStepCoT=false` 把原文当教训污染 ledger, 真实 LLM 走 2 步快速路径
会丢 3 段防幻觉的好处. `fallbackOnThreeStepFailure=true` 在 3 段失败时回退 2 步
跑 `consolidate()` 把全文当教训入 ledger, 完全失去 3 段的意义.

## 修复

- `ConsolidationConfig.useThreeStepCoT` 默认 `true` (老 `false`).
  真实 LLM provider (Ollama / OpenAI-compat) 走 3 段 `analyze → generate → verify + SourceRefValidator` 防幻觉.
  mock provider / test 走 2 步 fast path (`config: .fastDebug`).
- `ConsolidationConfig.fallbackOnThreeStepFailure` 默认 `false` (老 `true`).
  3 段失败 → 跳过该 candidate, 留明晚重试 (raw/ 没标 processed → gather 会重收).
  不回退 2 步 (那把全文当教训污染 ledger).
  `fallback=true` 仍允许 (mock-only 兼容, 真实 LLM 建议 `false`).
- `CounterBox.addError()` + `errorCount()` 失败计数可观测 (3 段失败时累加, 调试用).
- `MockLLMProvider.defaultHandler`: 老 2 步 fast path (系统+user 关键词判 phase: 分析师/提炼员/verify).
  3 段路径下 LLM 返 draft JSON, 2 步路径下 LLM 返 "YES"/"NO" 关键字.
- `DreamCycle` 4 tests 改用 `config: .fastDebug` (走 2 步 mock 兼容).
- `P8bDocAndRedactionTests` 期望改 `true` (productionDefault 3 步).
