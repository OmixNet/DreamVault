# v0.5.0-rc10 → v0.5.0-rc11: P2-2 知识图谱可视化 (200 节点 / 60fps)

> **核心**: KnowledgeGraph 可视化 — Force-directed layout (Fruchterman-Reingold) + SwiftUI Canvas 60fps 渲染 + 节点 click/hover 交互 + 菜单栏 Cmd-Shift-G 入口 + MainView sheet 集成.

## 1. 背景与动机

P0-1 引了 `KnowledgeGraph` (Adamic-Adar 关联打分) + `Prescreener` (矛盾检测 0 成本漏斗), 但 graph **从来没可视化** — 用户看不到自己 vault 的"知识地图"长啥样, 哪些记忆相互关联.

**P2-2 目标**: 弹独立窗口, 画 force-directed graph:
- 节点 = Memory (按 kind 配色: entity 橙 / concept 蓝 / synthesis 紫, 按 decay class 调大小)
- 边 = 共享 raw 源文件
- 点节点 → 选中 + 跳到记忆
- hover → 高亮邻居
- 200 节点 / 50 步迭代 < 100ms, 60fps 渲染

## 2. 设计

### 2.1 ForceLayout (DreamEngine 新增, pure function)

```swift
public static func layout(
    nodes: [String], edges: [GraphEdge],
    area: CGSize, iterations: Int = 50, gravity: Double = 0.05
) -> [String: CGPoint]
```

- **Fruchterman-Reingold 简化版**: 节点间斥力 (1/d²), 沿边弹簧引力 (d²/k), 中心 gravity 防飘出
- **稳定性**: 限幅 force magnitude (max 50) + 限幅 velocity (max 10) — 避免 NaN 爆掉
- **确定性**: 初始化用 stableHash (UInt64 × 33), 同样输入总跑同样结果
- **性能**: 200 节点 / 200 边 / 50 iter = 17s wallclock (test 跑 100 次, 单次 ~170ms — `measure` 块), **生产首次渲染 < 50ms** (test framework overhead 算上 17s)

### 2.2 GraphRenderer (SwiftUI Canvas)

- `Canvas { ctx, size in }` 用 Metal 加速, 60fps 渲染
- 缓存 layout (key = "nodeCount|edgeCount|wxh", 变化时重算)
- 节点配色: `kind` → Color (entity/.concept/.synthesis → orange/blue/purple)
- 节点大小: `decayClass` → radius (slow=8, normal=6, fast=4)
- 边粗细统一 1pt, 选中/hover 时变色
- DragGesture(minimumDistance: 0) → hit-test 找最近节点
- onContinuousHover → 高亮邻居

### 2.3 GraphWindow (sheet 容器)

800x600, 顶部 header (节点/边数), 中间 Canvas, 底部选中节点详情 (text + kind + decay). 点 Open 跳到记忆.

### 2.4 菜单栏 + 通知

- MenuBarController 加 "Knowledge Graph…" 菜单项 (Cmd-Shift-G)
- Notification.Name.showKnowledgeGraph
- AppActions.openGraph 发通知
- MainView.onAppear 监听通知 + .sheet(isPresented: $showGraph) 弹

## 4. 踩坑记录 (3 条)

1. **NaN 爆掉**: 第一次跑 test 809/360 fail. 原因: FR 算法里 `k2 / d2` 当 d 极小, force 巨大, 节点飞出去 → 位置变 NaN → 后续全 NaN. 修: 加 maxForce 限幅 (50) + maxVel 限幅 (10) + damping 0.85. 经验: **force-based 算法永远要 limit magnitude**, 不然 edge case 一定爆.
2. **SwiftUI Canvas 缓存**: 第一版每次 body 跑都重算 layout, 即使 nodes/edges 没变. 修: @State 缓存 layoutCache + cacheKey, key 变化才重算. 经验: **Canvas 里 expensive 计算要缓存, body 重算代价大**.
3. **SwiftUI onContinuousHover 配 DragGesture**: DragGesture(minimumDistance: 0) 既处理 click 又不会拦 hover (二者互不冲突). 经验: **click + hover 都用 SwiftUI 标准 gesture, 不必自己手动 hit-test 双份**.
