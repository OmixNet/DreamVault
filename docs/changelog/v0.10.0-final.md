## P0-1: O(N²) topRelated → maxHops 剪枝 + RelatedCache 24h TTL (缺陷报告 §1.1)

**根因** (`Sources/DreamEngine/KnowledgeGraph.swift` 老实现):
`topRelated(to:limit:)` 走 BFS 全图遍历, 1000 节点 vault 一次 O(N²),
用户 100 vault 调用 → 1000000 次节点访问, 真实 N=100 阶段已 2-3s 卡顿.

**修法**:
- `topRelated(to:limit:maxHops:)` 加 maxHops 参数 (默认 3), BFS 剪枝
- `RelatedCache` 新类, 24h TTL 缓存 (key: vault root + to + limit + maxHops),
  class + NSLock (跟 Persister 同步 throws 兼容, 不用 actor)

**新文件**: `Sources/DreamEngine/RelatedCache.swift` (~80 行)
**单测**: `Tests/DreamEngineTests/RelatedCacheTests.swift` (5 case)

## P0-2: String(contentsOf:) 全文读 → FrontmatterScanner 流式扫 (缺陷报告 §1.3)

**根因** (`Sources/DreamEngine/FrontmatterScanner.swift` 老实现):
老实现全文读 `String(contentsOf:)` 解析 frontmatter, 100MB 文件 O(filesize)
读 + 一次性 parse. 大 vault (1000 文件) 启动时 N×100MB 全读, 内存峰值 N×size.

**修法**:
- `FrontmatterScanner.hasProcessedFalse(url:)` 走 InputStream 4KB buffer 流式扫
- 找 'processed: false' 立即返 true, O(frontmatter size) ≈ O(几十行)
- 严格切片在 [fmStart, closeRange.lowerBound] 内, 避免误判 body 里的同名词

**新文件**: `Sources/DreamEngine/FrontmatterScanner.swift` (~70 行)
**单测**: `Tests/DreamEngineTests/FrontmatterScannerTests.swift` (8 case)

## P0-3: userDirtyWorkspace 抛错 → autoCommitUserChanges 自动 commit (缺陷报告 §2.2)

**根因** (`Sources/DreamEngine/DreamCycle.swift:175-181` 老实现):
dream run 启动时 `if !dirty.isEmpty { throw DreamError.userDirtyWorkspace }`,
强迫用户先手动 commit. 写完直接 Cmd+Q, dream 罢工.

**修法** (P3 修过, 8h 改动留尾巴): `autoCommitUserChanges()` 函数 —
- 检测 `git status --porcelain` 有用户改动
- 自动 `git add <白名单路径>` + `git commit -m "[dream auto-save]"`
- 走 "git log 含 [dream auto-save]" 验证
- 白名单 (P3-T3 修过): `notes/` `wiki/` `MEMORY.md`, 不动 `raw/` `vault_meta/`

**改动文件**: `Sources/DreamEngine/DreamCycle.swift:175-210`
**单测**: `Tests/DreamEngineTests/AutoCommitUserChangesTests.swift` (4 case)

## P1-1+2: 矛盾 UI 跳转 + NSTextView 行号 gutter (缺陷报告 §2.1 + §3.3 P1.1)

**P1-1 根因** (`Sources/dream/ConflictResolutionView.swift` 老实现):
view 存在但 UI 未 hook, 用户看不到矛盾, dream 报告写 .dream/reports/ 但
UI 收尾未接.

**修法**: ConflictResolutionView hook 到 EditorPane sheet 弹出 (SwiftUI
`.sheet` + state binding), 用户点 .dream/reports 里 "needsReview" 项 →
SwiftUI 弹 sheet → 点 "Resolve" 改 MEMORY 行 → 关 sheet.
**新增 scrollToConflict(anchor) API**: ScrollViewReader 跳转到锚点.

**P1-2 根因** (`Sources/dream/NSTextViewRepresentable.swift` 老实现):
NSTextView 包装, 没有行号, 编辑器看不出在哪行.

**修法**: `LineNumberRulerView` (NSRulerView 子类, 100+ 行), 装到
NSTextView 的 vertical ruler. NSTextView 自动算行数, ruler 画行号 gutter.

**新文件**: `Sources/dream/LineNumberRulerView.swift` (~120 行)
**单测**: `Tests/DreamTests/ConflictResolutionViewTests.swift` (3 case) +
`LineNumberRulerViewTests.swift` (4 case)
