# v0.5.0-rc6 → v0.5.0-rc7: P0-3 假 excerpt 闸门 (Fabrication Gate)

> **核心**: 给 Consolidator 加确定性闸门, 拦 LLM 在 3 步 CoT 路径上瞎编 excerpt. 0 LLM 成本, 100% 确定性. DreamCycle.Outcome 暴露 `rejectedFabricatedCount`, Persister 写 dream-report `## Fabrication` 段.

## 1. 背景与动机

P0-1 (cost pre-screener) 跑完后, P0-3 紧跟: 矛盾检测走 LLM 是必要的 (caller 真不知道两个观察有没有矛盾), 但 LLM 在 3 步 CoT 路径上**有时会编造 excerpt**——读不到源文件全貌, 自己造一个看起来像的话塞进 draft.

老路径是 verify: 拿 candidate 原文 + 源 excerpt 让 LLM 回答 YES/NO. 答 YES 进 ledger. **但 LLM 的 YES 不能保证 excerpt 真实来自源文件**, 它只是答 "结论跟证据自洽" 而已.

**P0-3 闸门**: 在 LLM 之后, **确定性** 比对 draft.sourceExcerpt (LLM 生成) 跟 `raw/<file>` 的真实内容. 归一化空白后 substring 检查. 不在源文件里 → fabricated → 拒收. 整夜 0 LLM 成本, 100% 准确率.

## 2. 设计

### 2.1 SourceRefValidator (新文件)

```swift
public enum SourceRefValidator {
    public static let minLengthForStrictCheck = 5
    public static func validate(excerpt:in:) -> Bool  // 归一化 + substring
    public static func validateBatch(refs:fileContentLookup:) -> (passed, rejected)
}
```

- **归一化**: trim + collapse whitespace (多空格/换行/tab 都视为单空格)
- **substring**: normalized excerpt 真在 normalized body 里
- **放行 (false positive 极少)**: 空 excerpt / 长度 < 5 / file 不在 lookup — 都是保守放行, 防回归
- **0 LLM 成本**: 全 Swift String 操作, 整数毫秒级

### 2.2 Consolidator 改造

`Consolidator.init` 加 `sourceContents: [String: String] = [:]` 参数. `Gatherer.GatherResult.sourceContents` 透传 (relPath → 脱敏后 body).

闸门在**两处**装:

- **3 步 CoT 路径** (line 467): draft (LLM 生成) 拿到后, 走 `checkSourceRefGate(draftExcerpt, draftFile)`, 拒收 + 累加 `rejectedFabricated`
- **2 步快速路径** (line 156): candidate 自带 excerpt (来自 Gatherer), 走同闸门, 防御性兜底 (用户改了 raw 文件导致 excerpt 不匹配)

并发路径不能用 inout (escaping closure 不能 capture). 用 `final class CounterBox` (@unchecked Sendable + NSLock).

### 2.3 公开 API 改动

- `consolidate(_:rejectedFabricated:)` / `consolidate3Step(_:consolidate2StepFallback:rejectedFabricated:)` / `consolidate3StepOne(_:fallback:rejectedFabricated:)` / `consolidate3StepSerial(_:fallback:rejectedFabricated:)` / `consolidateAndLink(_:against:rejectedFabricated:)` — **5 个函数加 inout Int 参数**
- `consolidateSmart(_:)` — 改返回 `(accepted: [Memory], rejectedFabricated: Int)` (旧 inout 改成返回值, 让 DreamCycle 装 Outcome 更顺手)
- 串行路径 inout 累加, 并发路径 (3 步并发 in 3StepSerial) 用 `CounterBox`

### 2.4 DreamCycle.Outcome + Persister

- `Outcome.rejectedFabricatedCount: Int` (P0-1 加了 PrescreenStats, P0-3 加 count)
- `Persister.Input.rejectedFabricatedCount: Int` 透传
- dream-report 末尾 `## Fabrication` 段 (`rejectedFabricatedCount > 0` 时显示, 静默 0 时不渲染)

## 4. 踩坑记录 (5 条)

1. **sed/perl 改 test call site 翻车**: 第一次 sed 把 `let out = try await` 也当 pattern 匹配了, 生成 `let out = try await let out = try await` 双前缀. 第二次用 Python, 但 `pattern.replace` 又把 `DecayClass.short` 替换失败 (因为 `.short` 是相对导入, 没 `DecayClass.` 前缀). 第三次用 sed -i '' 直接对单行, 干净. 经验: **改 test 调 API 用 sed 比 Python 安全** (单行 inline).
2. **3 步 CoT parser 要 array 不是 object**: parseDrafts 先试 `[MemoryDraft]`, 失败试 `DraftEnvelope.drafts`. mock JSON 写成 `{"text":...}` 单 object → 两边都 fail → throw → fallback=false → throws. 改成 `[{"text":...}]` array 才正确走 3 步 verify. 经验: **mock LLM 必须严格按 schema, 优先 array**.
3. **Mock LLM 按 callCount 区分 phase** (analyze / generate / verify), 不要按 `user.contains("analyze")` 关键词 — 老 mock 用的 "analyze" 不在 user prompt 里, 直接走 generate 逻辑. 改 callCount 最稳.
4. **2 步路径 1 次 LLM call = verify**: 3 步 mock 共享 = fail, 因为 2 步不调 analyze/generate. testFabricationGate2StepPath 用 YesLLM (永远返回 "YES") 才能走 verify path. 经验: **2 步 vs 3 步要分开 mock**, 不能复用.
5. **MemoryKind / DecayClass enum 名要查源**: 我写 `.observation` `.short` 编译失败, 实际是 `.entity/.concept/.synthesis` 和 `.slow/.normal/.fast`. **新建 Memory 时必须查 Models.swift** (grep `enum MemoryKind\|enum DecayClass` 走起).
